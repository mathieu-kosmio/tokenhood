# Summary

Tokenhood V2.1 is a model-free orchestrator: the platform never calls an LLM. All the intelligence (writing, code, review, estimation, case assessment) comes from the agents of registered contributors; the platform provides the rules, the state, the claims, the contracts, cross-verification and governance. Tokenhood is the first project open for contribution.

Its central promise: deliver to a maintainer work that is useful, understandable, verifiable and integrable with reasonable effort. V2.1 makes this the first success criterion and the main object of demonstration.

This document serves as a development plan. It is meant to be published in the `tokenhood` repository (folder `docs/specs/`) and broken down into missions.

**Changes in V2.1**, resulting from the critical review of V2:

| Topic | V2 | V2.1 |
| --- | --- | --- |
| Success criterion | Accepted missions | Net benefit for the maintainer: accepted, integrated, useful over time |
| Production flow | Redirection towards verification | Caps on work in progress per project, opening slowed down when review is saturated |
| Product promises | Stated as rules | Guarantee matrix: guaranteed, client-dependent or declarative, with mechanism and test |
| Budgets | Cap enforced on the client side | Three levels announced before the session: controlled, estimated, time or missions |
| Subscription compatibility | Asserted via the official client | Compatibility register per client and per mode, dated and tested |
| Capacity | Available tokens | Pledged, available and consumed capacity, and result obtained; separate measurement method and confidence level |
| Verification | Mandatory cross-review | Kept, with declared scope, binding to an immutable state, explicit waiting when no reviewer is available, defined end of chain |
| Protocol | States and claims | Mission and attempts, generation number, contract version frozen per attempt, waiting for arbitration, authoritative source per field |
| Governance | One process for all decisions | Three categories with delegation, rule of conduct for agents |
| Economy | "Tokens only" | Non-market contribution in agentic capacity, operations based on identified commitments |
| Selection | Automated in the MVP | Documented manual admission during the pilot, automation in lot 4 |
| First external project | End of the MVP | Lot 3, admitted manually |
| Lot 0 | Bootstrap | Bootstrap, four foundation deliverables carried out as missions, start of the pilot campaign |
